## 2026-10-23 — M1.1: make `main` build reproducibly

- **Branch:** `ci/m1.1-buildable-main`
- **What changed:**
  - Root `package.json`: `packageManager: npm@11.16.0` (turbo 2.x requires it). `engines.node` set to `>=24 <25`.
  - `.nvmrc` = `24`. Node 20 reached end-of-life in April 2026, and Node 24 is the active LTS and what this machine runs.
  - `package-lock.json` committed (lockfile v3, generated by npm 11.16.0).
  - `.npmrc`: removed `legacy-peer-deps=true`. The tree resolves cleanly without it, so peer-dep conflicts now fail loudly.
  - `apps/api/tsconfig.build.json` excludes `**/*.spec.ts` from `nest build`. Nest CLI picks this file up by default.
  - Fixed the spec import `../incident-state-machine.service` → `./`.
  - Removed `"test": "jest"` from `ai-sdk` and `kubernetes-sdk`. They had no tests and no jest config, so turbo would have failed or passed meaninglessly. Add the scripts back together with real tests.
  - `tsBuildInfoFile: dist/.tsbuildinfo` in the 6 `tsc`-built packages so that cleaning `dist/` also clears incremental state. Before this, a deleted `dist/` plus a stale buildinfo produced an empty build.
  - `.gitattributes` (`* text=auto eol=lf`) so Windows checkouts can't introduce CRLF into shell scripts and YAML.
  - `.gitignore`: `*.tsbuildinfo`.
- **Deliberately not changed (later milestones):**
  - Dockerfiles still use `node:20-alpine` and `npm install` without the lockfile. Moving them to `node:24-alpine` + `npm ci` belongs to M4 (container hardening) and needs a running Docker daemon to verify.
  - npm 11.16 warns that 8 packages run install scripts not covered by `allowScripts`. They still run today. Recording an explicit allowlist (allow prisma/bcrypt/esbuild/msgpackr; deny the `@nestjs/core` opencollective and `@scarf/scarf` telemetry hooks) is queued for M4.
- **Tests:** see [test-results.md](test-results.md) (M1.1 section).
